# Local retrieval checks and execution bounds

The reviewed tool catalog still contains eighteen tools and never falls back to Cloud.

`firecrawl_scrape` adds `metadata.localContentCheck` to its returned document. It checks target HTTP error status, empty Markdown, obvious loading-only tables, and short not-found pages. A failed/incomplete check sets the MCP result's `isError` and retains the source plus an explicit warning. The API transport can still be HTTP 200: this adapter check distinguishes transport success from content readiness. A `checked` heuristic result is not proof that the requested facts are correct; `accuracyVerified` remains false. JSON-only responses without Markdown are `not_assessed` unless the caller explicitly requested expected content, which cannot pass without source Markdown.

Optional `expectedContent` strings on `local_web_read`, `firecrawl_scrape` and `local_web_batch_scrape` must occur in returned Markdown. Batch HTTP/loading checks inspect the full retrieved source. If expected text occurs only after the 100000-character return cap, the item is explicitly incomplete with `expected_content_not_returned_due_to_truncation` and `missingReturnedExpectedContent`; `characters`, `returned_characters` and `truncated` distinguish retrieved from returned text. The proxy validates and removes this local extension before forwarding to the pinned official SDK. For dynamic tables, use a browser `wait` action targeting a populated row, then assert known content. Unknown live prices cannot be proved by searching only for the table title.

The batch helper validates every public URL before making requests, reads at most five URLs with two concurrent local requests, and returns results in input order. Each item retains target HTTP status and bounded metadata. HTTP404 is an error even when the API envelope is successful. `completed`, `failed`, and `incomplete` are separate counts. A loading-only result is incomplete, never a successful page. The shared helper request pool is two; monitor state mutations retain their existing file/SQLite guards. Monitor runs remain sequential and do not replace a prior successful snapshot with failed or loading-only content.

Batch callers may set `maxAge` (integer 0–604800000 milliseconds), `storeInCache` (boolean), `timeout` (integer 1000–20000 milliseconds per page) and `onlyMainContent` (boolean). These settings apply to every URL; the returned `scrape_options` echoes exactly the settings sent to the fixed local `/v2/scrape` endpoint. Existing defaults remain `maxAge:0`, `timeout:15000`, `onlyMainContent:true`; omitted `storeInCache` retains the API's default `true`. Explicit zero and false values are preserved. No arbitrary API fields, headers, proxy selection, or endpoint override are accepted. The transport allows five seconds beyond each page's API timeout; with the helper pool otherwise idle, five pages in three waves have a 75-second transport budget at the largest allowed timeout, below the gateway's 90-second execution deadline. Other helper traffic can consume the shared two-request pool; queue and gateway deadlines still apply under contention.

For a fresh comparison, use the same `maxAge:0`, `storeInCache:false`, `timeout:15000`, and `onlyMainContent:true` on both individual and batch requests. `maxAge:0` requests a new Firecrawl fetch rather than accepting its cached content; it cannot guarantee that the target site's CDN or origin bypasses its own cache. `storeInCache:false` controls storing this result and is not a substitute for `maxAge:0`. Batch was already fresh by default before these options were exposed; their addition does not establish a new speedup. Returned batch Markdown remains bounded to 100000 characters per page, with explicit truncation, so speed alone does not establish identical completeness.

Blocking companion and search/map HTTP work uses a two-worker dispatcher with at most four waiting tasks. It no longer blocks reading new stdio messages. Official scrape calls are already forwarded asynchronously: the pre-change diagnostic showed simultaneous API dispatch and useful overlap, so the Mac itself was not universally serialized.

Map is routed to the fixed local `/v2/map` API so `SEARCH_PROVIDER_UNAVAILABLE` and HTTP503 remain typed tool errors instead of the official SDK's `INVALID_ARGUMENT` wrapper. Useful partial map results, warnings and discovery diagnostics are preserved.

Gateway response `_meta.localGateway` reports gateway queue/bridge/total time. Proxy `_meta.localExecution` reports its queue/service time. The production gateway also retains bounded private timing records in `.local-state/remote-gateway/timings.jsonl` (10MB, three files). They contain tool names, timestamps and durations only, never arguments, URLs, passwords, OAuth tokens or page text. Gateway authentication and SSRF protections remain enforced. Admission is two active calls/four waiting calls, with a 60-second queue wait and a separate 90-second service deadline. Queue expiry/full failures are recorded once with an enumerated outcome; expired work is not dispatched. Some clients hide private response metadata, so use the local timing records when independently checking execution overlap.


See [the testing guide](../docs/TESTING.md) for reproducible source tests and opt-in live acceptance. `node local-bench/verify-read-only.mjs --launcher "$PWD/local-plugin/bin/firecrawl-mcp"` exercises the full-format reader on public pages after the local service and locked MCP runtime are installed. Its results and screenshots remain private under `local-bench/var/`. Client dispatch timing and gateway service timing must be reported separately.
